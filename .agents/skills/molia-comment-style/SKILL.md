# Molia 注释规范

写注释或清理噪音注释前，读 `docs/comment_style.md`（权威口径，含先例提交），按其执行。

## 要点

注释写「为什么」：设计意图、不变量、协议约定、边界条件、性能取舍、算法来历。

只写现状：不写迁移对照（「旧实现…」「与旧版一致」）与变更叙事（「不再有…」「已删除 Y」），
把历史句翻成对当前行为的正面描述。

发现即清理：

- 注释掉的代码 / IDE 提示残留 → 整行删除；
- 复述代码的废话与英文模板残留（`// Constructor`、`// Getters`）→ 删除或改简洁中文；
- 工单 / 阶段 / 波次出处（`issue #8`、`Wave 7`、`Phase 2`）→ 去掉出处短语，保留设计要点；
- 同一事实多处重复 → 留信息量最大、离使用点最近的一处；
- 装饰分隔线：纯 `// ----` 整行删；标题含别处没有的实质信息时去掉装饰、保留一行普通注释。

必须保留：公共 API 文档注释、示例 payload、ASCII 图示、`// ignore:` 指令、TODO/WIP，
以及现行迁移与兼容逻辑（DB 版本迁移、旧偏好键、旧缓存互读、平台旧版 API 兜底）。

## 执行

1. 只改注释文本，不改代码 / 字符串 / 断言；
2. 按模块分批提交 `chore(comments): 清理 X 噪音注释`，与功能改动分开；
3. 每批跑 `flutter analyze --no-pub` + `flutter test --no-pub`；
4. `git diff` 自查：不留悬空括号、断句、半截引用。
