# Molia 文案规范

写或改用户可见文案前，读 `docs/copy_style.md`（权威口径，含对照表与先例提交），按其执行。

## 要点

面向用户，只回答「能不能用」和「怎么办」；实现细节一律不上面（API 路径、模块/协议名、
内部状态词、性能术语、部署方式）。一条一个意思，副标题尽量一句话；能删的补充说明就删，
删不掉的放对话框或日志。

黑话改白话（常用对照）：

- 对端 / 候选地址 → 其它设备 / 可用地址；载荷 / 拉取 / 推送 → 数据 / 接收 / 上传；
- 快照 → 同步数据；会话（内部义）→ 状态；取链 → 播放链接；
- 探测端口 / 广播 / 组播 → 发现端口 / 自动发现；回环、link-local → 局域网地址；
- 端点 / 绑定 / 注册 → 连接端口 / 启动 / 生效；前台服务 → 后台继续；
- LRU 淘汰 → 自动清理最早的缓存；断点续传、直链、签名地址 → 从头重下；
- 孤儿文件 / 半成品（.part）→ 残留文件 / 中断的临时文件；远端 → 云端；
- 凭证 / 令牌 → 密钥 / 访问密码；口径 / 主题角色 / 骨架实现 → 删除，改写成结果或怎么办；
- 具体依赖名（AppIndicator、xdg-desktop-portal、Docker）与引擎名（JS 引擎、媒体元数据）→ 删除或换白话。

保留产品词：音源、渠道、脚本、歌词、桌面歌词、封面、歌单、收藏、省流模式、口令、设备、
同步、下载、缓存、取色、队列。不改 key。

必须保留：不可逆操作的风险说明与隐私同意书的事实要点、用户需要照做的具体值
（文件名模板变量、IP/域名示例、端口范围、快捷键修饰键、Android 权限名）、同步失败
结论（细节在日志）、脚本免责声明。

## 执行

1. zh / en 成对改，占位符 `{name}` 保持一致；
2. `flutter gen-l10n` 更新 `lib/l10n/app_localizations*.dart` 一起提交；
3. 测试字面量断言按新文案同步（有 l10n 实例时优先引用 `l10n.<key>`）；集成测试
   finder 同步更新并跑 `tool/agent/test.sh linux`；
4. `flutter analyze --no-pub` + `flutter test --no-pub` 全量过；
5. 批量文案改动一个 `chore(l10n): ...` 提交，与功能改动分开。
