# ADR-0002：内置 AI 推歌（用户自备 Key + 闭卷生成 + 本地解析）

- 状态：已采纳
- 日期：2026-10-11
- 相关：`lib/services/ai/**`、`lib/providers/ai_dj_provider.dart`、
  `lib/domain/models/ai_dj.dart`、`lib/playback/local_playback_service.dart`（enqueue）、
  issue #9；能力输入来自 Phase 1 听歌统计（issue #8）

## 背景

项目定位原为「纯播放器，**明确不含 AI 功能**」。项目 owner 提出「根据历史听歌让 AI
推荐歌曲」的需求，且明确了形态：**应用内**调用在线 LLM（非导出到外部工具），
用户自备 API Key，同时保留导出 JSON 的能力。Phase 1 已完成事件级听歌统计
（`play_events` + 导出 JSON），天然可作为画像输入。

需要一次显式的定位变更记录：应用将首次出现「把用户数据发往第三方服务」的通道。

## 决策

1. **定位调整**：AI 推歌是**可选功能**（默认关闭、配置入口在设置›内容›AI 推歌），
   不属于核心播放链路；AGENTS.md 的「明确不含」移除「AI 功能」。
   **定位按「个性推荐」对齐**（2026-10 修订）：主体是**今日推荐列表**——持久化、
   可浏览、可随时播放的推荐内容；「推歌（电台）」只是把列表喂进队列的自动化
   （`enabled` 功能开关与 `status` 电台状态解耦，退出队列不关功能）。入口：
   发现页「今日推荐」区（查看全部）+ 设置；**不再有播放页 AI 徽标**。
2. **形态**：内置在线 LLM，OpenAI-compatible Chat Completions 协议
   （Base URL / API Key / 模型可配，预设 DeepSeek / OpenAI / 自定义）。
   **不提供内置 Key 与服务端中转**；Key 存本机凭据库（明文 SQLite，见 ADR-0016 修订）。
   Web 平台隐藏入口（CORS 与密钥安全）。
3. **数据边界**：上行「聚合画像 + 已听清单最近 100 首」（2026-11-05 起最近
   播放与已听清单合并去重；本地去重仍读最近 500 首，上限集中在
   `TasteProfileBuilder`）；不含 raw payload、不含设备信息；首次开启前置
   隐私确认弹窗；错误信息不含 Key。
4. **生成方式：闭卷生成 + 本地解析**。LLM 只负责选歌（纯 JSON：
   `title/artist/reason`），本地 `CatalogService.search` 在用户已启用的可搜索
   音源解析成可播放曲目，解析失败丢弃（页面折叠展示「未找到」）。
   推荐结果 100% 可播放，且不依赖平台相似度 API。
5. **模式（电台）语义**：批次默认 24 首（2026-11-05 起；原 10）；队列剩余 ≤5 首且当前队列就是 AI 队列时后台
   续推（先消费列表剩余，吃完了生成新批）；跳过 = 被切走时未达
   `min(30s, 50%×时长)`（复用统计口径），**只做曲目级排除**；
   喜欢 = 收藏（回流下一批）；连续 3 次失败自动停止续推；退出电台保留队列。
   列表侧另有单曲「换一首」「不感兴趣（可撤销）」与反馈面板；跨天**不自动生成**
   （不静默消耗 token）；缓存有效期设置已由 2026-10 修订移除（见下）。
6. **播放内核新增 enqueue**：`PlaybackFacade/Backend.enqueueTracks` +
   `LocalPlaybackService.enqueueTracks`——顺序模式追加队尾；洗牌模式把新下标
   扩展到排列尾部（`PlaybackShuffleOrder.extend`），轮末重洗覆盖全队列。

## 2026-10 修订（issue #37）：多批历史 / 静默补歌 / 偏好与渠道 / 发送透明化

原决策不变（内置、自备 Key、闭卷 + 本地解析、默认关闭），以下语义替换旧版
「单批今日推荐 + 低水位显示续推中」的实现：

1. **多批历史**：推荐从单批改为「索引 + 每批一键」的持久历史
   （`ai_dj_history_index_v1` / `ai_dj_history_batch_v1:<id>`）。旧单批键
   `ai_dj_pending_batch_v1` 首次加载迁移为 `restored` active，迁移成功才删旧键；
   启动只加载索引 + active，详情懒加载。保留 20 批 / 400 首 / 30 天，active
   永不自动清理；删除 active 回退最近一批，清空历史保留 active。
2. **active 与历史语义**：显式「生成推荐 / 换一批」与历史「播放这批 / 设为
   当前」才切换 active；手动补批与自动补歌只追加队列 + 写历史，不切换 active。
   历史「播放这批」强制替换队列并起播（功能关闭时按普通队列播放，不启动补歌）。
3. **静默自动补歌**：队列剩余 ≤5 首且上下文为 AI 队列时后台生成，追加队尾 +
   写历史（`origin=autoFeed`），**不产生任何可见进度/提示**，不切换 active；
   完成时队列已播完则从新追加第一首静默续播。连续 3 次失败停止；显式操作优先
   并可取消在途静默任务。手动补批是显式操作（可显示进度），仍不切换 active。
4. **可调批次**：24/48/96，默认 24（2026-11-05 起；原 10/20/30/50，默认 10）；
   影响 LLM count、本批元数据与自动补歌
   数量，「换一首」固定 1；改动后下一次生成生效。
5. **推荐偏好**：`AiPreferences`（风格 / 场景 / 语言 / 年代 / 探索度 /
   只推荐没听过的 / 补充要求 / 批次大小 / 自动补歌 / 发送范围 / 种子快照）
   持久化在 `kAiDjPreferences`；偏好页即时保存、不自动生成。
6. **发送范围**：按勾选裁剪上行数据（紧凑行格式）；收藏与自建歌单最初默认关
   （opt-in，2026-11-05 起改为默认发送），注入 `LibraryStore`，有上限地只发
   歌名 / 歌手 / 歌单名，并加入本地排除集合；读取失败降级为空、不阻塞生成。
7. **找歌渠道**：不在用户界面暴露；解析按音源页渠道顺序遍历全部可搜索渠道，
   不设数量上限，停用渠道不参与。推荐行不显示命中渠道；未解析项只重新搜索、
   不重新调 LLM。
8. **发送透明化**：预览与实际共用 `buildPrompt`（同输入文本相等）；发送范围 +
   本次预览 + 上次发送 + 上次 LLM 原始返回收进弹窗，可复制；上次发送与原始
   返回只存内存，不落盘、不打日志。
9. **反馈记忆**：不感兴趣 / 喜欢 / 种子持久化在 `kAiDjFeedbackMemory`（上限
   200/200/20）；种子下一批成功生成后消费；提供清空 AI 记忆。
10. **进度与取消**：仅显式生成有 `profile → model → resolving` 进度、等待秒数、
    解析 done/total 与取消；首屏脉冲骨架、轮播细进度条、单行换一首局部进度；
    静默补歌不设置 `AiDjProgress`。动画尊重 `MediaQuery.disableAnimations`。
11. **移除死设置**：多批历史不再消费「推荐缓存有效期」，AI 页删除该行，
    provider / settings store / 登记键一并删除。

### 2026-10-22 修订：UI 收敛

- 推荐偏好改为即时保存，删除「保存偏好」按钮与「偏好已更新」提示；
- 每批默认 24（2026-11-05 起；原 10）；批次大小只在推荐偏好页出现；
- 找歌渠道不再作为偏好项暴露，解析按音源页顺序遍历全部可搜索渠道；
- 内置平台规范顺序统一为 QQ → 网易 → 酷狗 → 酷我 → 咪咕（音源页与发现页）；
- 发送内容改为弹窗（本次发送 / 上次发送 / 上次返回），主页面只留入口。

### 2026-10-24 修订：提示词瘦身与双语

- 画像从逐条 JSON 改为紧凑行（`[段名]` + `、` 分条），去掉每条重复的 key；
- 最近播放 200→50、发送的已听清单 500→100（本地去重仍读 500）、时段取
  Top 12、来源 Top 8；Top 歌手/歌曲保留 50，收藏/歌单上限不变；
- system prompt 只保留角色定位；质量约束与一行 JSON 样例放在 user 末尾
  （DeepSeek/OpenAI 的 JSON Output 要求 prompt 含 `json` 字样与格式样例）；
- 提示词文案跟随应用语言（中文/英文），包括段名、偏好值、reason 语言与
  请求行；歌曲名/歌手保持原语言；
- 上一批 + 未解析项 + 当前会话队列进入 `[本批排除]`，同时用规范化键做
  本地兜底，模型忽略排除清单时也不会重复；
- `response_format` 被 400 拒绝且退回成功后，按 `baseUrl|model` 记住，
  后续不再重复发送带参数的探测请求；
- 输出 `max_tokens` 当时保持 4096，避免 JSON 被中途截断（2026-11-05 起按
  批次量在 4096–8192 之间动态设置）。

### 2026-10-25 修订：删除旧单批迁移

旧单批键 `ai_dj_pending_batch_v1` 的首次加载迁移已删除：启动只读历史索引
（`ai_dj_history_index_v1`）与 `activeBatchId`，索引缺失即视为没有历史；旧键
不再读取、不再迁移，也不会生成 `restored` 批次。`AiDjOrigin.restored` 已从枚举
删除，批次来源只剩 `refresh` / `autoFeed` / `manualFeed`；「迁移旧推荐」不再是
合法来源。上面 2026-10 修订第 1 条中的旧键迁移描述仅记录历史。

### 2026-11-05 修订：收藏排除、解析、默认范围与反馈入口

1. **收藏本地排除与上行解耦**：收藏列表始终读取并进入本地去重集合（已听 /
   收藏 / 歌单），即使「收藏」发送范围未勾选也不会推荐已收藏曲目；只有勾选
   时才把歌名/歌手写入提示词，收藏数据不会经 `[已听过]` 等其它段落泄漏上行。
2. **解析后二次过滤**：LLM 返回的标题/歌手与实际命中曲目可能不一致，解析成
   真实 `Track` 后再按收藏的 `sourceKey:songId` 稳定键与规范化 `title|artist`
   键过滤一次；「重新找未解析」同样过滤，覆盖同一首歌换音源的情况。
3. **JSON Output 严格解析**：按 DeepSeek JSON Output 官方实践，请求带
   `response_format`，提示词含 `json` 字样与输出样例；解析只接受约定的
   `{"songs":[{"title","artist","reason"}]}` 合法 JSON，不再从正文里提取或
   修补。JSON Output 会把无法识别的内容替换成空格，空正文自动重试一次，
   仍为空才报 `aiDjBadResponse`；`max_tokens` 按批次量在 4096–8192 之间
   动态设置，避免大批次 JSON 被截断。
4. **默认发送范围**：收藏 / 自建歌单改为默认发送（新默认八项全开）。存量
   偏好若没有 `sectionsVersion`、恰好是旧默认六项且从未确认过收藏/歌单，
   自动升级为新默认；新版保存过的状态不再迁移，自定义或明确关闭过的范围
   保持原样。首次隐私确认与发送范围文案同步说明。
5. **反馈入口**：反馈与记忆从 AI 页移到推荐偏好页；偏好页入口行只显示
   本轮 / 长期条数摘要，仍打开同一弹窗（本轮、长期记忆、多来点这种、
   清空 AI 记忆）。
6. **提示词精简**：删除 `[收听来源]`；`[最近播放]` 与 `[已听过]` 合并为
   去重后的 `[已听过]`；不再发送播放次数、收听分钟、最近播放秒数/完播
   标记；要求行只引用实际发送且非空的段；输出 JSON 契约上移 system
   prompt；不再写可用渠道；同歌手上限按批次放宽为 2/3/4。
7. **批次与等待 UI**：每批默认 24，可选 24/48/96；旧设置 50 迁移为 48，
   其余旧值回退 24。生成卡改为三步进度（整理偏好 → AI 选歌 → 本地找歌），
   并显示目标数量与等待秒数。
8. **子页导航**：推荐偏好 / 历史不再新开 sheet，改为 push 到最近的 Navigator；
   设置入口复用设置弹层内层，发现页入口由共享的
   `lib/widgets/modal_page_navigator.dart` 在 AI 页弹层内提供内部 Navigator
   （含预测返回归属与返回栈），AI 页首屏在标题栏补关闭按钮。

### 2026-11-06 修订：生成进度与输出预算

1. **生成请求不固定 `max_tokens`**：DeepSeek 等推理模型会把 `max_tokens`
   计入思维链，固定 4096–8192 可能在 JSON 输出前被耗尽；生成请求省略该
   参数，交给服务端默认预算，`testConnection` 仍保留小预算。
2. **进度数据更完整**：`AiDjProgress` 增加 `targetCount` / `resolved` /
   `unresolved`；生成卡按阶段显示目标数量、已找到数量与等待秒数，找歌阶段
   标题改为「正在本地找歌」，「重新找一次」不再显示成完整生成。
3. **找歌进度按每首完成推进**：`_resolveAll` 不再等整个并发分片，单曲完成
   即回调，100ms 节流并在最后一首强制发送；同时增加单音源探测超时（默认
   10s），超时按未命中处理，避免慢源把整批进度卡死。
4. **视觉与可达性**：细进度条的确定值做平滑动画；生成卡与发现页进度条带
   无障碍语义；发现页首次生成（只有骨架）也显示细进度条。自动补歌仍保持
   静默，不进入任何进度 UI。
5. **超时与解析兜底**：生成请求的整请求超时改为 180s（连接测试仍 30s），
   避免推理模型正常生成被 30s 误杀；JSON 模式连续空正文时回退一次纯提示词
   请求；`parseRecommendations` 支持代码围栏、前后说明、裸数组、常见包装键、
   尾逗号与截断后的完整对象，纯文本列表仍然不猜测。

## 后果

- 应用出现首条用户数据外发通道：默认关闭 + 确认弹窗 + 只发聚合/近期数据，
  关闭开关不采集（统计侧另有独立开关），删 Key 即断联；
- 播放内核获得队列追加能力（AI 续推使用；未来队列面板可复用），
  洗牌追加语义有单测覆盖（老歌不被重排、追加歌轮内可播）；
- LLM 的可用性与费用由用户自己的 Key 承担；失败统一归一化为 `SourceFailure`
  并保留当前播放（不打断听歌）；
- Phase 1 的逐事件统计与导出 JSON 直接作为画像输入与兜底能力，无需返工；
- 定位文档（AGENTS.md）与术语（GLOSSARY）随实现更新。
