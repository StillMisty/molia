# ADR-0023：展开播放页不新增常显传输排

状态：已采纳（2026-11-14）。相关：`lib/pages/nowplaying.dart`、
`lib/widgets/player.dart`、`lib/widgets/player_cover_deck.dart`、
`lib/widgets/playback_transport.dart`、`docs/architecture.md` §6。

## 背景

UI 收敛审计建议在移动端展开播放页的标题下增加一排常显的「上一首 / 播放 /
下一首」，理由是主操作不可见，且同一动作在迷你条、顶栏、桌面底栏/播放页有
不同形态。

## 决策

**不新增常显传输排。** 展开态继续以封面为唯一主操作：

- 点按中心封面播放 / 暂停；左右邻封面或横滑切歌；进度排保留收藏与播放模式。
- 显式传输控件继续存在于迷你条、非播放页顶栏、桌面底栏与桌面播放页。
- 不因为「统一」把低频控件搬进展开态；封面点击是刻意的大目标手势，不是遗漏。

## 理由

- **视觉**：展开播放页的主体是封面堆叠与歌词/队列/信息页；再加一排按钮会与封面
  争夺视觉重心，破坏当前已经打磨好的沉浸式版式。
- **人体工学**：封面是整页最大的可点区域，点按播放/暂停比精确命中一排小按钮更
  容易；左右邻封面天然承担上一首/下一首，手势与视觉位置一致。
- **一致性边界**：迷你条、顶栏、桌面底栏已经承担「看得见的传输控件」；展开态
  不需要复制同一套控件。

## 后果

- 首次使用展开态需要知道「点封面播放」；这是沉浸式视觉的代价，由迷你条/顶栏的
  显式控件和封面语义标签兜底。
- 封面必须保留可读的播放/暂停语义，但不再增加可见按钮。
- 未来若重做播放页，必须同时评估封面堆叠、迷你⇄完整飞行、手势与 200% 字号，
  不允许单独插入一排传输控件。
