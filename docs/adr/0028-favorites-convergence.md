# ADR-0028：收藏页保持单一列表形态，封面默认书脊

- 状态：已采纳
- 日期：2026-11-14
- 相关：`lib/pages/favorites.dart`、`lib/widgets/collection_picker.dart`、
  `lib/widgets/collection_spine.dart`、`lib/widgets/playlist_cover.dart`、
  `lib/services/library/playlist_folder_prefs.dart`、
  `lib/providers/collection_presenter.dart`、`lib/providers/library_collections.dart`、
  ADR-0022、`docs/architecture.md` §6、`test/app/favorites_layout_test.dart`

## 背景

收藏页在一次次的「功能补齐」里同时承担了四类职责：合集管理、曲库浏览
（专辑 / 歌手 + 智能列表）、列表运营（封面 / 描述 / 分享 / 导出）与曲目列表
（搜索 / 排序 / 重排 / 多选）。标题行最多堆到 5 个图标，模式切换行常驻在
所有合集下面，宽屏又有一套合集左栏和一整套表格列。用户反馈是
「过于复杂，失去了原本简洁的设计」；分享列表被明确认为是无意义功能。

问题不是某个控件不好看，而是**同一页存在太多平级入口和两套合集入口**。

## 决策

1. **收藏 / 历史 / 本地歌曲 / 自建列表只保留单一列表形态**：
   - 标题行 = 书脊 + 合集名 + 随机 / 搜索 / ⋮（有曲目时最多 3 个图标）；
   - 不再有常驻的 `歌曲 / 专辑 / 歌手` 模式切换行；
   - 不再有宽屏合集左栏，所有宽度都从标题点进合集弹层；
   - 不再有收藏页的宽屏表格列 / 表头，历史播放时间进副标题，本地缓存标签
     改成行尾小图标。
2. **低频动作统一进标题 ⋮**：排序 / 调整顺序 / 清空历史 / 导入本地歌曲 /
   最常播放指标 / 编辑详情 / 换封面 / 导出 / 全部下载。搜索态只剩返回 + 输入，
   不再挂第二套溢出菜单；不允许同一动作出现两个常驻图标。
3. **新增「曲库」伪合集**：专辑 / 歌手浏览只在曲库内出现（轻量切换），
   曲库条目两行显示 `N 张专辑 · M 位歌手`；不做「全部歌曲」子视图。
4. **智能列表与分组收起**：
   - 智能列表作为曲库下方的折叠组，默认收起，标题只有「智能列表」，不带数字；
     当前选中智能列表时自动展开；
   - 自建列表分组首次默认收起，仅当前列表所在分组展开，之后记忆用户选择；
   - 固定入口（收藏 / 历史 / 本地歌曲 / 曲库）不参与拖动排序，只有自建列表可排序。
5. **删除无意义功能**：
   - 列表分享全链路删除（按钮、分享弹层、列表海报布局 / 渲染、分享源、测试）；
     听歌统计 / 年度报告的共享海报基础设施保留；
   - 列表描述编辑与标题副标题删除；`description` 数据 / 同步字段保留，不做
     schema 迁移；
   - 移除独立 `PlaylistHeaderOverflow` / `PlaylistShareButton` 组件。
6. **封面口径统一**：
   - 所有合集默认显示书脊细条（约 3dp 宽、随标题高度缩放、`colorScheme.primary`
     实色、小圆角）；不再用中性封面占位图标；
   - 我的收藏与自建列表都支持自定义封面；有自定义封面显示封面，移除 / 读取
     失败回落到书脊；
   - 列表封面支持 GIF / WebP 动图：选图时原样保留字节，按实际格式落盘
     （`.gif` / `.webp`），同步记录携带真实 MIME 并校验字节一致；
     单张上限 2MB，与同步上限相同，保证「能选就能同步」。

## 后果

- 收藏页恢复单一层级；新增一个常驻图标、一个新的顶部模式行、或一套新的合集
  入口，都必须先质疑是否真的需要，并补布局测试。
- `description` / `coverKey` 仍留在 `PlaylistInfo` 与同步记录里；只是 UI 不再
  编辑 / 展示描述。未来若要恢复，必须重新评估列表标题行密度。
- 动图封面是明文二进制文件，同步只接受 JPEG / GIF / WebP 且 MIME 必须与
  实际字节一致；PNG 等其它格式仍被跳过。
- 回归钉子：`test/app/favorites_layout_test.dart`、`test/local_library_ui_test.dart`、
  `test/playlist_experience_test.dart`、`test/services/custom_cover_store_test.dart`、
  `test/sync_cover_adapter_test.dart`。

## 修订：桌面宽屏恢复表格列（2026-11-14）

单一入口、无合集左栏与标题 ⋮ 的决策保持不变；用户反馈宽屏双行列表在标题与
行尾时长之间留下大片空白，因此收回「不再有收藏页的宽屏表格列 / 表头」这一条：

- 内容宽 ≥ `TrackRowColumnSpec` 阈值时，收藏 / 历史 / 本地歌曲 / 自建列表 /
  智能列表显示表头与列（标题 / 歌手 / 专辑 / 时长；播放历史多一列播放时间，
  窄屏仍在副标题里保留播放时间）；
- 窄窗口继续用简洁双行列表，行高与列构成仍由 `TrackRowSurface` 单一来源决定；
- 新增列不改变合集的播放、多选、重排、右键菜单与行尾缓存标记语义，也不恢复
  宽屏合集左栏或常驻模式切换行。
