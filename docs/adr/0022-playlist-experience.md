# ADR-0022：列表体验（描述 / 封面 / 分组 / 分享 / 交换格式 / 队列存为列表）

状态：已实施。相关规格：#54；共享 schema v3 由 #56 / ADR-0021 拥有。

## 背景

列表原先只有名称与曲目。本 ADR 记录跨模块的取舍：列表元数据如何进入同步记录、
封面字节如何与列表行解耦、分组为什么不是实体、M3U 与全保真文件各自承担什么，
以及设备本地 UI 状态放在哪里。

## 决策

### 列表行与同步记录

- `playlists` 复用 v3 的三列：`description` / `folder` / `coverKey`；不新增表、索引
  或版本号。
- `PlaylistSyncRecord` 宽容扩展 `description` / `folder` / `coverKey`：写端总是写出
  （空值也写，显式清除可表达），读端对旧形状默认空串 / null。整条记录仍是
  whole-record LWW；旧版本设备重命名会清掉新字段，因此同组设备必须一起升级。
- `folder` 只是字符串，没有分组实体、空分组、嵌套或排序。重命名 / 删除分组在
  一个事务里逐行取新版本、逐行写同步记录；删除只把 `folder` 置空。

### 封面

- 封面键命名空间是 `playlist:<syncId>`；收藏列表使用固定 syncId
  `__favorites__`，因此键也稳定。首次写封面前补齐缺失的 syncId。
- 字节继续走 `CustomCoverStore` 的 `custom_covers/` 与 covers 同步类别；列表行只
  保存指针。替换写新文件名，删除走封面墓碑；500 KB 上限与 JPEG-only 不变。
- 列表封面没有「全局默认封面」语义：UI 缺图显示中性列表图标，不使用默认封面。
- 远端封面先于列表记录到达时，展示按 `syncId` 推导键仍能找到图片。

### 分享与海报

- 海报固定 1440×1920 PNG（宽度固定、高度取上限），离线只用调用方提供的本机封面
  字节；马赛克 9 格，空槽是中性占位，不重复用图。
- 纯文本分享最多 500 首，超出用「还有 N 首」；不写链接、账号、设备名或路径。
- 绘制原语（裁切 / 文本 / 受限解码）抽到 `services/poster/poster_draw.dart`，歌词
  海报与列表海报共用。

### 交换格式

- M3U8 是通用格式：`#EXTM3U` + `#PLAYLIST` + `#EXTINF` + `#MOLIA:<sourceKey>:<songId>`
  + 位置。下载副本写原在线键 + 绝对路径；本地导入写稳定身份
  `#MOLIA:local:file:<uuid>` + 绝对路径。规格里的 `local:<绝对路径>` 会让文件
  移动后失去身份，按 #56 的稳定身份口径改为 `local:<localKey>`；导入解析同时接受
  旧键（路径不存在时自然落到未解析复核）。
- 在线曲目没有平台页地址时才用 `molia://track/<base64url>` 回退。
- `.molia.json` 复用备份 envelope，只含目标列表 / 曲目 / 封面记录；导入走既有
  备份 LWW，按 `syncId` 合并不重复。
- M3U 的 `#MOLIA` 解析只查本机已知记录（下载 / 历史 / 库内列表），不搜索网络、
  不按标题猜；普通在线 URL 不做抓取，未解析项全部进入复核并显式跳过。

### 设备本地 UI 状态

分组展开 / 收起是设备本地偏好，直接存 SharedPreferences
（`playlist_folder_collapsed_v1`），不进设置注册表、不随同步或备份走。重命名分组
不迁移旧折叠状态。

## 后果

- 列表描述 / 分组依赖整组设备升级；这是 whole-record LWW 的直接代价。
- 分组不是实体：并发编辑单个列表可能让它在下次重命名前留在旧分组。
- M3U 是有损格式；全保真只能走 `.molia.json`。
- 有分组时隐藏列表拖动排序，避免跨分组拖动语义含糊；无分组时行为不变。
