# ADR-0040：问题排查改为诊断支持中心——结论优先、分层自检、证据可复制

- 状态：已采纳
- 日期：2026-11-23
- 相关：`lib/pages/diagnostics_page.dart`、`lib/pages/diagnostics_log_page.dart`、
  `lib/widgets/diagnostics/`、`lib/providers/diagnostics_provider.dart`、
  `lib/providers/diagnostics/`、`lib/domain/models/diagnostics.dart`、
  `lib/services/diagnostics/`、`lib/app/bootstrap/diagnostics_checks.dart`、
  `lib/services/diagnostics/system_checks.dart`、`lib/widgets/settings/about_settings_section.dart`、

## 背景

问题排查页已能导出诊断文件，但仍按「数据块」组织，用户要先读懂数字和状态才知道
下一步做什么：

- **没有结论优先**：首屏是概览、取链计数、最近问题、渠道检查四块平铺；没有一句
  「现在能不能用、哪里不正常」的摘要，异常退出这类跨会话事实也没有位置。
- **检查只覆盖半个音源**：现有健康检查只测「渠道搜索 + 取链」，播放流首字节、
  播放后端、数据库可读写、账号与同步状态都不在检查范围内。最常见的「搜索正常但
  播放 403」「数据库打不开」「同步一直失败」只能靠导出文件后人工判断。
- **最近问题逐条平铺**：同一渠道的网络抖动会占满整张卡；没有按原因 / 渠道归并，
  也没有「发生了几次、最近一次是什么时候」的聚合，重试入口和问题详情混在一起。
- **错误形状绑死在渠道上**：`HealthChannelResult` 以「渠道 + 搜索 + 取链」为唯一
  形状，无法表达应用、播放、存储、账号这些跨域检查；新增一类检查就要新增一套页面
  渲染与文案映射。
- **报告只有保存一个出口**：不能先预览、不能复制；保存日志保留 20MB 是合理的，
  但复制整份 20MB 文本既超出剪贴板承载力，也容易把大段日志误发出去。
- **日志不可见**：页面只显示「正在记录 / 不可用」，没有查看器和筛选器。用户要看
  日志只能先导出文件；旧页面头注释把「没有日志查看器 / 筛选器」写成了长期决定，
  当时是为了避免页面变成数据展示页，但排障仍然需要看日志。
- **动作边界不清**：页面只有「检查渠道」和「导出」，没有「重试失败项 / 重启音源
  引擎 / 去对应设置」这类可逆恢复动作，也没有明确「不做自动上传 / 遥测」。

## 决策

### 1. 页面定位与信息顺序

把「数据展示页」改成**支持中心**，固定顺序：

1. **状态摘要**：一句话结论（正常 / 有 N 项需要处理）、最近一次自检时间、上次是否
   异常退出；
2. **分层自检**：按域分组列出检查项与结果；
3. **最近问题**：分组去重后的问题列表，可展开看单次记录；
4. **日志**：日志状态一行 +「查看日志」入口（设置子页）；
5. **报告出口**：复制 / 预览 / 保存 / 分享，隐私与大小提示收在出口附近。

摘要与自检在上、证据与出口在下；用户先拿到「要不要管」，再决定看哪一层。

### 2. 统一诊断检查模型（`DiagnosticCheckResult`）

所有检查统一为一份只读模型（放在 `lib/domain/models/diagnostics.dart`）：

- `id`：跨版本稳定的检查标识（枚举，测试、文案与报告共用）；
- `group`：app / sources / playback / storage / sync（应用 / 音源 / 播放后端 /
  存储与数据库 / 账号与同步）；
- 状态：`ok` / `warning` / `failed` / `skipped`；本轮未执行是 `skipped`，运行中的项由
  当前运行表示，不写进最终结果；
- 耗时、可选的渠道标识与稳定短值（版本号、后端名、表版本等），稳定短值由检查实现
  负责脱敏；失败只保留 `FailureKind` / l10nKey / retryable。

用户可读结论、下一步提示与可逆动作由页面按 `id × 状态 × 失败类别` 映射，不进模型。

一次自检是 `DiagnosticCheckRun`：固定顺序的检查结果 + 起止时间 + 是否取消。渠道健康
检查保留自己的顺序 / 冷却 / 取消与内部结果形状，接入统一运行时投影为「音源」域的
一组检查，页面只消费统一结果；最近失败仍走内存环形缓冲，页面读取时按「同渠道 +
同失败类别」分组去重，组内保留次数、首次与最近时间，展开才显示单次时间与渠道；
分组是只读记录上的纯函数，不改写事实。

模型不持有原始异常、`SourceFailure.message`、响应正文、URL、请求头或 Cookie；
分组（同渠道 + 同失败类别）、文案与排序都只基于只读记录投影，不回写事实。原始异常
与凭证不得为了「详情更全」进入页面或报告。

### 3. 分层自检覆盖

检查按域固定，域内顺序执行，互不阻断：

- **应用**：版本 / 构建 / 平台、上次退出（异常退出标记）、通知权限、日志 sink 状态；
- **音源**：脚本引擎健康、渠道搜索、取链（沿用当前偏好音质）、对解析结果发起一次
  有界的播放流首字节读取（验证状态码、`PlayableStream.headers` 与可读性，读完立即
  关闭，不缓存字节）；
- **播放后端**：播放器 / 音频后端可用性、最近一次播放失败与恢复链走到第几次尝试
  （`Playback attempt`，只读）；
- **存储与数据库**：主库结构与完整性、一次轻量查询、日志可写；
- **账号与同步**：B 站登录态（已登录 / 过期 / 匿名，不读 Cookie 值）、同步是否
  启用、传输可用性与最近一轮结论。

单条检查有超时，整轮可取消并保留已完成结果；同一时间只跑一轮，冷却规则沿用现有
健康检查。**打开页面不自动跑检查、不做后台轮询、不扫日志**；自检只由用户动作触发，
避免把网络和磁盘成本带进日常设置浏览。

### 4. runner、service 与探针注入

`lib/services/diagnostics/` 仍是唯一实现：

- 诊断 runner（`diagnostics_runner.dart`）只依赖端口：应用信息、目录搜索 / 取链、
  播放流首字节读取、播放后端能力、数据库计数 / 查询、账号与同步状态。生产适配器
  在 `lib/app/bootstrap/diagnostics_checks.dart` 装配，测试注入假实现；探针不绕过
  `SourceFailure` 归一化。
- 单项检查超时 7 分钟（覆盖渠道 × 搜索 / 取链 / 流的最坏情况），源检查另设 6 分
  30 秒总预算；渠道检查订阅 `SourceHealthChecker.changes`，逐渠道增量写入
  「搜索 / 取链 / 流」三条结果，不重跑探针，取消或超时前已写入的结果保留。
- `DiagnosticsService` 继续持有最近失败缓冲、最近一轮运行、轮转日志 sink 与运行
  标记；组合根在 catalog / playback 栈之前构造它，catalog 建好后挂上检查器。
- `DiagnosticsProvider` 只保留 service 订阅、刷新与动作转发，纯投影 / 报告 / 日志
  控制面在 `lib/providers/diagnostics/`；对外是窄 `ValueListenable`：`summary` /
  `checkResults` / `issueGroups` / `session` / `appInfo` / `reportState` / `logsState` /
  `metrics`，页面各卡片只订阅自己那一份，不整页刷新。

### 5. 最近问题分组与异常退出标记

- 失败缓冲仍是只读事实源，页面投影成「问题组」：同渠道 + 同失败类别归为一组，
  显示次数、首次 / 最近时间与可重试性；单次记录只在展开后出现。
- 新增设备本地**运行标记**：启动与前后台切换时记录最后可见阶段（前台 / 后台 /
  已正常关闭）；下次启动读到上次仍停在「前台」时，在摘要与报告里给出「上次可能
  异常退出」并指向日志尾部（后台被系统回收不算异常）。标记只存时间、版本与阶段，
  不同步、不采集使用行为、不是遥测。
- 播放恢复链的 `attempt`（失效取链缓存 → 原地重取 → 整首重试 → 自动换源）作为只读
  诊断字段进入播放检查详情与问题记录；不改变恢复策略，也不与统计里的 `play_events`
  （一次实际播放）混用同一名称。

### 6. 日志查看器与设置子页

- 设置 › 问题排查下的只读「日志」子页（`lib/pages/diagnostics_log_page.dart`），
  不新增一级导航入口；
- 经 `LogTailReader` 读取当前与轮转文件的**有界尾部**（512 KB / 500 条），级别 /
  文本筛选只在内存结果上执行，不改写文件；不提供删除 / 清空（轮转自动处理）；
- 日志目录的唯一来源是 `RotatingFileLogSink.directory`，导出器与日志读取器都由
  组合根注入，不另拼路径；
- 落盘前已按 `redactSecrets` 脱敏，读取展示与导出再走同一套脱敏规则；
- 日志入口在问题排查页只占一行（状态 + 最近时间），不把日志正文铺在首页。

这明确取代旧页面头注释里「没有日志查看器 / 筛选器」的决定；「不做图表、不新增一级
导航」仍然成立。

### 7. 报告出口、上限与默认落点

诊断报告 = 现有纯文本诊断包：环境、自检结论、问题组、数据库计数与日志尾部。

- **预览**：页面内查看报告，上限 64 KB（`diagnosticsReportPreviewMaxBytes`）；
- **复制**：独立小上限 128 KB（`diagnosticsCopyMaxBytes`，常量集中在导出模块并被
  测试钉住），只含结论、问题组与日志末尾；超出部分明确写出省略；
- **保存 / 分享**：沿用 20MB 硬上限（`defaultDiagnosticsBundleMaxBytes`），完整日志段
  仍按最新内容截断并声明省略；分享写临时文件走系统分享，平台没有分享入口时退化为
  保存；
- 报告默认只在本机生成与保存，**不自动上传、不做遥测**；分享必须由用户显式发起，
  并保留「可能包含歌名和本地路径」的提醒。

三档共用同一份组装实现与脱敏，避免不同出口在截断或编辑上漂移。

### 8. 只做可逆修复动作

页面只提供：重新检查、重试失败项、重启音源引擎、打开对应设置页 / 日志页、复制 /
预览 / 保存 / 分享报告。不提供删除数据、清空缓存、重置设置、退出账号、自动上传或
任何「一键修复」写操作；需要改设置或清理数据时，跳转到用户可自行确认的入口。
恢复动作都来自用户的明确动作，不做自动重试循环。

## 后果

- 用户先看到结论与下一步，再按域定位；同一问题不再重复占满列表，日志不用先导出
  就能看。
- 检查从「渠道搜索 + 取链」扩展为五个域；现有健康检查器保留自己的顺序 / 冷却 /
  取消，接入统一运行时后投影成 `DiagnosticCheckResult`，页面与文案映射只消费统一
  结果。
- 打开页面仍保持轻量（无自动检查、无日志扫描）；代价是完整自检可能持续数分钟，
  且会发起真实搜索、取链与一次首字节请求——因此必须由用户触发并可取消。
- 复制与预览是有意不完整的证据（大小上限 + 省略声明）；完整证据仍走保存 / 分享的
  20MB 报告。分享入口依赖平台能力，缺失时退化为保存。
- 运行标记与问题分组带来新的测试面：异常退出判定、分组去重、单检查超时 / 取消、
  渠道增量结果、首字节探针不缓存字节、三档上限与脱敏一致性。
- 没有新增遥测、崩溃上报或远程支持通道；「日志子页」是设置内的本地只读视图。

## 后续

- 核心、五域探针、页面、日志子页与 provider 拆分已落地；provider 已按纯投影 /
  报告 / 日志控制面拆分，`summary` / `checkResults` / `issueGroups` / `session` /
  `appInfo` / `reportState` / `logsState` / `metrics` 这组读口保持不变。
- 同步更新 `GLOSSARY.md` 与 `docs/architecture.md` 的相关条目；`docs/pitfalls.md`
  里指向旧分区名的观测入口在改名时改成模块说法。
- 若将来要把自检做成后台周期任务、加入自动修复或上传通道，需要新的 ADR 与真实
  使用证据；本次不预留遥测接口，也不引入「自动上传」开关。
