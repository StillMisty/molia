# ADR-0027：设置首屏按域分组，低频长表单下沉子页

- 状态：已采纳
- 日期：2026-11-14
- 相关：`lib/pages/settings_page.dart`、`lib/widgets/settings/`、
  `lib/pages/bottom_nav_settings_page.dart`、`lib/pages/backup_restore_page.dart`、
  `docs/architecture.md` §6、`test/widgets/settings_page_test.dart`

## 背景

设置首屏曾是 6 张语义卡（外观 / 播放 / 歌词 / 内容与来源 / 数据与存储 /
通用与关于）。一次改版删掉了「通用」「数据」两个纯目录子页，把所有行直接铺到
首屏；「不设目录页」的方向没错，但低频长表单也一起留在了首屏，结果桌面首屏
约 48 行、移动端约 45 行。

行数与归属同时失控：

- 播放卡混了四类事情：播放行为、音源与音质、网络省流、曲库加入位置；
- 音源管理在「内容与来源」，默认音质 / 自动换源 / 省流却在「播放」；
- 「数据与存储」11 行把缓存、下载、统计、导出导入、同步与问题排查挤在一起；
- 「通用与关于」把启动页、底部导航拖拽列表、语言、震动、应用名称、托盘、
  窗口、快捷键与更新挤在一起；
- 卡内顺序没有统一原则：有的按常用程度，有的按实现顺序；设备本地项与跟人走
  的项混排，只在卡底用一句笼统说明。

首屏条目过多、归属要读完整行才知道、顺序无法预测——这是信息架构问题，不是
某个控件的问题。

## 决策

1. **一级固定为 9 张语义卡**：外观 / 播放 / 歌词 / 音源与在线服务 /
   曲库与存储 / 数据与备份 / 通用 / 桌面（仅桌面平台挂载）/ 关于与更新。
   同一域只允许出现在一张卡里，卡名必须能预测卡内内容。
2. **卡内排序统一为三条**：常用 → 少用；开关 / 选择 → 入口；平台通用 →
   平台独占。每张卡目标 ≤7 行（省流展开音质与封面子项时例外，≤9）。
3. **不设纯目录子页，只下沉两类内容**：低频长表单（底部导航拖拽排序）与
   低频破坏性动作（导出 / 导入 / LX 收藏迁移，合并为「备份与恢复」子页）。
   子页只做一类事；设置首屏仍保留完整入口，不出现「点进去还是目录」的层。
4. **不按同步边界分组**。跟人走 / 设备本地仍混排在同一语义卡中，但卡底提示
   只描述该卡内的本地项（播放卡只提淡入淡出与随机偏好，通用卡只提震动，
   桌面卡提托盘与窗口，曲库卡提文件夹 / 下载 / 缓存），不再用一句覆盖全卡。
5. **宽屏两列按内容量显式分列**：左列 `{0, 2, 4, 6}`（外观 / 歌词 / 曲库 /
   通用），右列为播放 / 音源与在线服务 / 数据与备份 / 桌面 / 关于；列优先
   瀑布式，短卡不按行留空。
6. **这是信息架构变更，不是数据变更**：所有设置项 key、读写行为、同步类别
   与深链保持不变；改版不新增迁移，也不改用户已存的值。

## 后果

- 首屏桌面约 48 → 40 行、移动端约 45 → 37 行；单卡最大行数从 16 降到 7
  （省流展开 9）。用户可以先读卡名再找行，不必逐行判断归属。
- 底部导航排序与备份 / 导入各多一次点击：换来低频长表单与破坏性动作离开
  日常设置区，误触面更小；启动首页锁定、至少保留一个标签等行为不变。
- 分区落位规则可复用：新设置项先找域，再按常用程度插入；单卡放不下时优先
  拆子页，不新增一级目录页，也不把同类项拆到第二张卡。
- 代码上新增 `about_settings_section.dart`、`data_backup_section.dart`、
  `desktop_settings_section.dart`、`library_storage_section.dart` 与两个子页
  文件；`data_settings_section.dart` 删除，`general_settings_section.dart`
  收缩为通用卡。l10n 新增卡标题 / 子页标题 / 分卡本地提示，删除三个旧卡
  标题键；设置页测试改为按新卡分组断言，同时保留全部既有行 key。
- 若将来还要继续压缩首屏，先在这 9 张卡内收行或复用现有子页；重新引入
  纯目录页需要新的 ADR 与真实使用证据。
