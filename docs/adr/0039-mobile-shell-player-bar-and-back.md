# ADR-0039：移动端顶栏播放条是唯一迷你播放器；播放页展开即完整

状态：已采纳（2026-11-21）。相关：ADR-0023（传输控件口径）、
ADR-0024（播放页圆点手势）、`lib/app/shell/app_shell.dart`、
`lib/app/shell/player_flight.dart`、`lib/pages/nowplaying.dart`、
`lib/pages/nowplaying_gestures.dart`、`lib/widgets/player.dart`、
`lib/widgets/now_playing_controller.dart`、`docs/architecture.md` §6。

## 背景

移动骨架原先有两条「迷你播放器」：壳层顶栏播放条（封面 + 歌名/作者 +
播放/暂停 + 下一首 + 进度线）和播放页内的 72dp 迷你条（同一批信息与
收藏 / 上一首 / 播放 / 下一首）。播放页收起时保留页内迷你条，于是：

- 同一屏出现两条内容几乎相同的迷你播放器，阅读顺序与点击目标都重复；
- 收起态仍占 72dp，歌词 / 队列区被一条「不是当前页主操作」的条压住；
- 进入播放页时可能落在上一轮手动收起的迷你态，用户看到的是一个「空的
  播放页」，还要再点一次才完整；
- 两套共享封面飞行（顶栏 ⇄ 播放页、页内迷你 ⇄ 完整）使用不同参数的弹簧
  （380/1.0 与 380/0.8），起止锚点与容差拖尾互相干扰，收起 / 展开的落点
  容易差一帧。

## 决策

### 1. 移动端顶栏播放条是唯一迷你播放器

- 资料 / 发现、收藏、播放页**收起态**：顶栏显示封面 + 歌名/作者 +
  播放/暂停 + 下一首 + 平直进度线。它承接所有「不在完整播放器里」的
  传输入口。
- 播放页**展开**：页内是完整播放器；顶栏让位为品牌位（应用标志 +
  应用名），不再有播放控件。
- 播放页收起高度为 **0**：不再有页内 72dp 迷你条。收起后本页直接把整块
  高度让给歌词 / 队列 / 信息，顶栏播放条在飞行落点回来承接封面与歌名。
- 进入播放页（从其它一级页、底栏 / 导航轨、顶栏曲目区）**总是展开**。
  收起态只能在播放页内主动收起后到达；离开再进入会重新展开，不继承
  上一轮的收起态。
- 展开 / 收起与进入 / 离开共用现有的顶栏 ↔ 播放页 `PlayerMorphFlight`
  封面飞行；页内不再有第二套迷你 ⇄ 完整飞行。
- 桌面骨架与移动宽版式（两栏播放页）没有收起态
  （`miniCapable = false`）：播放页始终完整，顶栏永远没有可收起的播放条。
  桌面**单栏**同样不能收起——否则收起后没有顶栏播放条承接，会得到一个
  高度 0 且无法恢复的播放页。

收起态失去的入口是刻意的：页内迷你条上的收藏 / 上一首随迷你条一起
删除。收藏仍在展开进度排，上一首仍由封面手势（左侧邻封面 / 横滑）与
队列承担；顶栏播放条按 ADR-0023 的传输控件口径只保留播放/暂停 +
下一首，不在窄条里塞第二组按钮。

### 2. 返回层级按「一级页」重写

- 移动端资料 / 发现、收藏、播放页收起态：系统返回直接退出应用。
- 播放页展开：第一次返回先收起（高度归 0、顶栏播放条回来），第二次
  才退出应用。
- 页面级 `BackClaims`（多选 / 搜索 / 排序 / 弹层）仍然优先，壳层在
  `BackClaims.any` 时让位；这一条不变。
- 桌面 Esc：播放页队列打开时先收队列；否则展开态先收起；其它一级页
  不再「回上一目的地」，保持原命令落点（非播放页 no-op）。

「回上一目的地」的历史层级被删除：三个一级目的地之间是平级切换，
返回应该退出应用，而不是在页面间倒退。桌面保留 Esc 的「收队列」肌肉
记忆，但不再把 Esc 当浏览器后退键用。

### 3. 新设置：回到播放页时显示歌词

- 键 `shell_now_playing_lyrics_on_enter`，默认**开**，跟人走
  （`SyncCategory.settings`）。
- 位置：设置 › 高级设置 › 播放细节。
- 文案：`回到播放页时显示歌词` / `从其它页面进入播放页时，先显示歌词`。
- 只在「从其它一级页进入播放页」时生效；播放页内部打开的二级页返回
  不重置当前 tab（用户没有离开播放页，不应被拉回歌词）。
- 关闭时保留播放页上次停留的 tab。

### 弹簧参数

页内高度动画用 motor expressive spatial 弹簧（380/0.8，允许轻微过冲）；
共享封面飞行用 `aospSpatial` 无过冲弹簧（380/1.0，落定帧零速度交接）。
两者参数不同，允许一帧级差异：起飞锚点分两帧抓、回飞比切页晚一帧
（16ms），肉眼不可辨。不要为了「完全同帧」把高度动画改成无过冲或把
飞行改成 expressive——前者会让展开 / 收起失去跟手感，后者会破坏
共享元素落位的零速度交接。

## 理由

- **只留一个迷你播放器**：顶栏播放条在三个一级页都在场，信息与控件
  已经完整；页内再放一条只是重复，还把内容区压短。收起高度归 0 后，
  「收起播放器 = 专心看歌词 / 队列」，语义比「缩成另一条迷你条」干净。
- **进入即展开**：用户点播放目的地 / 顶栏曲目的意图是「看当前播放」，
  不是一个上一轮残留的视图状态。收起态要由用户在当前页面主动选择。
- **没有承接面就不给收起**：桌面 / 宽版式 / 桌面单栏没有顶栏播放条，
  提供收起只会制造「点了没反应」或「收起后无法展开」。宁可少一个手势，
  不让状态不可逆。
- **返回即退出**：一级页是平级的根目的地，倒退历史没有信息量；展开的
  播放器是唯一的页面内层级。把返回留给「收起播放器 / 退出应用」两层，
  比三步历史更好预测。
- **默认歌词**：从资料 / 收藏进入播放页，用户通常想看当前播放的歌词，
  而不是上次停在的队列或信息页；偏好跟人走，跨设备一致。

## 后果

- 页内迷你条相关代码、`CoverAppearance.mini`、
  `miniCoverFallbackIconSize`、`Player.miniBarKey` 与页内迷你 ⇄ 完整
  飞行删除；`CoverAppearance` 只剩 `bar` / `page` 两个端点。
- `NowPlayingController` 增加 `expand()` / `collapse()` / `miniCapable`，
  tab 版本改名为 `tabRequestVersion`；重复点击播放目的地不再经
  `ShellReselectSignal`，由壳层直接切换展开态并发起共享飞行。
- 收起态没有收藏 / 上一首按钮：这是用「一条顶栏条」换「两条迷你条」
  的取舍，不再以「少一个按钮」为由把页内迷你条加回来。
- 桌面单栏播放页的拖拽 / 圆点收起请求被忽略（布局能力位为 false），
  不会留在半截高度。
- 未来若重做移动端播放页，必须同时评估顶栏播放条、收起高度 0、进入
  即展开、返回层级与新设置；不允许单独恢复页内迷你条或第二套封面飞行。
