# 注释规范（含噪音注释清理标准）

> 适用范围：`lib/`、`test/`、`integration_test/`、`tool/` 下的 Dart / JS 注释。
> 本体例先例：`git show d71d379`（封面模块噪音注释清理）、`git show a6ebdc8`（无意义文档清理）。

## 1. 总则

- 注释写「为什么」：设计意图、不变量、协议约定、边界条件、性能取舍、算法来历；
- 不写只复述代码的注释；注释以中文为主，公共 API 用 `///` 文档注释；
- 指向仍存在的文档 / ADR / 章节的引用是有效指针，保留
  （如 `docs/pitfalls.md #20`、`docs/architecture.md §2.1`、ADR-0001）。

## 2. 噪音注释（发现即清理）

1. **注释掉的代码 / IDE 提示残留**
   `// debugPrint('更新 widget 失败: $e');`、
   `// bool _isLoading = false; // isLoading can be final`、
   `// super.key, // Parameter 'key' is not used` → 整行删除。
2. **复述代码的废话注释**（尤其英文模板残留）
   `// Constructor`、`// Getters`、`// Search state`、`// Add tracks if available`
   → 删除；夹带真实信息的改写为简洁中文。
3. **工单 / 阶段 / 波次出处**
   `（issue #8 已拍板）`、`Wave 7`、`Phase 2`、`M3E-P2`、`阶段 2 改道`、
   `阶段 0 只定义契约` → 去掉出处短语，保留设计要点本身，不发明新的阶段词。
   例：`/// 切歌视觉（#6 安静化）：` → `/// 切歌视觉：`
4. **迁移对照**：引用已被删除的旧实现 / 旧版行为做对比的句子
   （`与旧实现一致`、`旧实现 fetch 完全不可测`、`改道前完全一致`、
   `已随 #6 删除`、`（删除入场特例后的等价替代）`、`原实现为 420ms…`）
   → 改写为只描述**当前**行为；整句只为对比而存在的删除。
   例：`/// 无旧曲时只播放入场动画（与旧 build 内首帧检测等价）` →
   `/// 无旧曲时只播放入场动画`
5. **重复解释**：同一事实在 doc / 字段 / 行内注释里说了多遍 →
   保留信息量最大、离使用点最近的一处。
6. **变更日志式注释**：`不再有 X`、`已删除 Y`、「以前怎样现在怎样」→
   翻成对当前行为的正面描述（`侧邻位不再有入场演出` →
   `侧邻位随页面层自身淡入，无独立入场演出`），纯历史叙述删除。
7. **与代码明显不符的过时注释**：按代码事实修正注释措辞（不改代码）。
8. **装饰性分隔线**
   - 纯分隔行（`// --------`、`// ========`、`// ########`）→ 整行删除；
   - 带标题横幅（`// ---- 标题 ----`）：标题只是分区名 / 复述附近代码的
     整行删除；标题含别处没有的实质信息（约束、口径、前提）的，
     去掉虚线装饰、保留为一行普通 `//` 注释，或并入最近声明的文档注释；
   - ASCII 图示 / 状态机图 / 示例 JSON 不是分隔线，保留。

## 3. 必须保留

- 「为什么」设计意图、不变量、协议约定、边界条件、性能取舍、算法来历；
- 公共 API 文档注释、示例 payload、ASCII 图示、状态机图；
- `// ignore:` / `// ignore_for_file:` / `// dart format off` 指令；
- TODO / WIP 待办标注；
- 描述**现行**迁移 / 兼容逻辑的注释：DB 版本迁移（v2→v3→v4）、
  用户偏好旧键迁移、旧版缓存 JSON 互读、平台旧版 API 变体兜底
  ——这些是现行功能约束，保留内容，仅去掉无关出处号。

## 4. 执行方式

- 只改注释文本，不改代码 / 字符串 / 测试断言；
- 改完用 `git diff` 自查，不留悬空括号、断句、半截引用；
- 按模块分批清理（与功能改动分开提交），提交信息用
  `chore(scope): 清理 XX 模块噪音注释`；
- 每次清理后跑 `flutter analyze --no-pub` + `flutter test --no-pub`。
