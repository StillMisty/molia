# Molia 0.4.0

0.3.0 之后的稳定版本，汇总 0.4.0-beta.1 ~ beta.5 的全部内容：桌面补上系统媒体
集成与音频会话生命周期，移动端播放器统一成一条顶栏播放条，万级曲库与统计页
完成一轮性能收口，收藏、同步与设备本地设置的一批问题一并修复。

## 新增

### 桌面

- **输出设备丢失自动暂停**：Windows 拔耳机、蓝牙断开、USB DAC 掉电，以及 macOS /
  Linux 默认输出消失时，播放立即暂停，不会继续从内置扬声器满音量外放。新增设备、
  在两个仍然可用的输出之间主动切换都不会误触发；暂停后不自动恢复。
- **Windows 音量合成器显示 Molia**：以前这条音频流显示为 `JustAudioMediaKit`，
  现在与应用同名，能一眼认出。
- **macOS 播放菜单**：菜单栏新增「播放」菜单，含播放 / 暂停、上一首、下一首，与
  托盘菜单是同一批动作，跟随界面语言；键盘、鼠标与 VoiceOver 用户都能用。
- **Linux 桌面入口**：应用菜单可按「音乐 / 播放器」搜到 Molia，系统通知归属应用，
  声明单主窗口并带启动反馈。

### 播放器

- **新增「回到播放页时显示歌词」**：默认开、跟人走，入口在 设置 › 高级设置 ›
  播放细节；只在从其它一级页进入播放页时生效，播放页内部开二级页返回不会重置
  当前标签。

## 改进

### 播放与音频

- **打开 Molia 不再打断其他应用**：以前 iOS 冷启动会激活音频会话，覆盖
  「与其他应用同时播放」；现在按设置走，混播设置在冷启动后依然有效。
- **暂停后释放音频会话**：暂停 20 秒、停止或退出后释放会话与焦点，其他播放器可以
  恢复；宽限期内继续播放不需要重新激活。
- **Android 混播真正生效**：「与其他应用同时播放」开启时，导航、语音提示会压低音乐
  并在结束后恢复，而不是抢独占焦点；关闭时保持独占。播放中切换该设置立即生效。
- 通话、Siri 等中断结束后自动续播更可靠；焦点确实拿不回来时给出可重试提示。

### 移动端播放器

- **只保留一条迷你播放器**：顶栏播放条（封面 + 歌名/作者 + 播放/暂停 + 下一首 +
  进度线）成为不在完整播放器时的唯一入口。播放页内的 72dp 迷你条删除，收起高度
  归 0，歌词 / 队列 / 信息区拿到完整空间。
- **进入播放页总是展开**：从资料 / 发现、收藏、底栏或顶栏曲目区进入都是完整
  播放器，不再继承上一轮手动收起的迷你态；展开 / 收起与顶栏↔播放页共用同一套
  封面飞行。
- **返回层级更符合预期**：资料 / 发现、收藏、播放页收起态按系统返回直接退出应用；
  播放页展开时第一次返回先收起，第二次才退出。桌面 Esc 优先收起打开的队列、
  其次收起播放器，不再被当成浏览器后退键。

### 性能

- **万级曲库浏览更少卡顿**：浏览索引不再在界面线程逐行解码曲目原始数据，改为用到时
  才解码；曲库超过 2000 行时索引构建放到后台 isolate。10k 行实测原本占界面线程
  22.7–33.1ms 的索引构建不再阻塞界面。
- **切收藏不再整库重读**：收藏 / 取消收藏只增量更新当前浏览索引，10k 收藏下仍在
  120Hz 帧预算内（`jank8=0`，p99 4.30ms）；批量、换源、同步与导入仍走整库校准。
- **统计页开页明显更顺**：两张热力图改为一整张网格批量绘制，开页 p99 从 126ms
  降到 42–53ms（约 −45%），最差帧 216 → 约 150ms；悬停提示、读屏逐格数值与
  离开后的 100ms 消失都保留。
- **桌面窗口缩放更顺**：隐藏页不再参与布局与尺寸重建，窗口尺寸、DPR、断点变化
  也不会让隐藏页在后台重建；封面解码按 256/384/512/600 逻辑档位取档，拖动窗口
  不再每像素换一张解码图。同机 Linux profile 实测 build p50 5.80 → 3.38ms
  （−42%），仓库 resize 场景 jank 6 → 1。

### 其它

- **内置渠道不再为查能力提前拉起脚本**：内置音源的原生搜索 / 取链 / 歌词走自带
  声明，纯脚本音源仍按需激活；每个传输实例的重试间隔也相互独立。
- 桌面品牌胶囊收口：高度 40dp、内边距 12dp，长名称省略，窄窗只显示 LOGO。
- 桌面发布包不再携带运行期用不到的 JNI 运行时（Linux 实测约 157 KB），发布前的
  体积守卫会拦住残留。

## 修复

- **改封面、改名后收藏页不再卡在加载中**：这类操作只刷新列表信息，不再丢掉当前
  列表的曲目缓存；已删除列表的缓存会正常作废，不会被异步写回。收藏页在后台静默
  刷新被跳过时也不再因为空值崩溃。
- 收藏页切换合集后滚动条拖不动：列表重建后找回正确的滚动位置与手势绑定。
- 收藏页的本地歌曲行不再显示「已缓存」下载图标：本地文件本来就不是下载。
- 桌面 / 宽版式下残留的播放页展开态不再吞掉返回键与 Esc。
- 窄屏与交互审查一批收口：桌面窄窗有音量入口；350–399 宽迷你条标题不再被挤没；
  封面的无障碍语义与侧邻光标正常；200% 字号下布局不再溢出；窄窗口下分段行自动
  降级为下拉；下载与缓存设置合并为一页；360 宽下多选栏不再撑破。
- 万级曲库下的搜索 / 歌单详情 / 收藏合集刷新与下载、AI 推歌操作细节收口：等待中
  的任务可取消、删除有确认、失败可重试。
- 听歌同步：自动轮在途时的手动补跑会按请求合并成一轮；待发标记只在本轮真的传输
  成功时按类别清掉，零对端与失败轮不再误清。
- 听歌统计：加载失败或过期结果不再推进统计窗口，跨午夜与乱序返回不会把数据算进
  错误的时间段。
- 设备本地设置（音量、播放手感、引导标记）：损坏的 JSON 值自动回退，旧音量键
  整组兜底，多个实例并发写入改为串行，不再互相覆盖。
- Windows 默认输出按播放后端实际使用的多媒体角色判断，不再只跟随控制台角色而
  跟丢设备。

## 内部

- 原生互操作层（ADR-0038）落地：桌面 FFI 与 Android JNI 改为生成绑定；Android 的
  系统文件选择器（SAF）、下载入库、下载通知、桌面小组件更新统一走 Pigeon 类型化
  通道，失败仍回退旧通道。架构测试强制边界，CI 校验生成物漂移。
- 工具链跟到最新 stable，版本只以 `AGENTS.md` 的「工具链」一行为准。
- 架构收口：音源能力统一经 SourceRouter 路由；听歌同步的排队、补跑合并与交付台账
  收进 SyncRoundQueue；收藏键 / 行 / 计数收进 FavoriteFact；设备本地偏好收进
  DeviceSettings；壳层展示判定收进 ShellPresentation；听歌统计新增纯 Dart 投影
  模块。用户可见行为不变。
- 新增架构守卫：禁止 `MediaQuery.of` 整树订阅、原生互操作边界、设备本地设置直连
  SharedPreferences 扫描、发现端点缓存直调扫描。
- 性能工具：新增 `jank8`（work > 8.33ms）口径与两个 120Hz 桌面场景（10k 收藏切换、
  统计页开页），帧场景支持筛选，新增无设备 UI 预览脚本。

## 升级说明

- 正式版与 0.3.0 及各测试版（0.4.0-beta.N）使用同一签名，可直接覆盖安装；构建号
  单调递增，应用内更新能正常识别。测试版用户升级到本版后走稳定渠道。
- 本项目仍处于快速迭代期，不承诺跨版本数据与协议兼容；需要保留的资料请先备份。
