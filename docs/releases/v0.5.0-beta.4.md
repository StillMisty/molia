# Molia 0.5.0-beta.4

0.5.0 的第四个测试版：状态层整体迁移到 Riverpod 与不可变快照，页面级状态离开即释放；
曲目菜单统一加入分享入口，并修掉同步期收藏心形不跟随、记住上次页面设置失效与发现页
加载时的版式跳动。

## 改进

### 状态层迁移

- **状态改为不可变快照**：播放、资料库、搜索、下载、同步、歌词、诊断等状态统一为
  `@immutable` 快照 + 控制器，读取方只拿到冻结数据，配置变更不会在半路改写正在
  展示的列表。
- **页面状态离开即释放**：页面与弹层状态改为 auto-dispose，不再在启动时全部常驻；
  返回后再进入会重新取当前数据。
- **重建范围收窄**：队列、歌词、搜索结果等快照集合按版本号复用，变化时只重建真正
  依赖它的那一小块；本地歌曲行列表改为零拷贝只读视图。

### 曲目分享

- 曲目行菜单（⋮ / 桌面右键）与歌曲信息页的「来源」行统一为同一套分享动作：复制
  曲目 ID、分享平台页面、打开平台页面、分享歌曲文件（未下载时先下载再分享），
  脚本源与本地曲目也能复制 ID 或分享已下载文件。

### 其他

- 播放目的地改用音符图标；发现页歌单标签加载中补骨架占位，切换标签不再跳版。

## 修复

- **同步期收藏心形不跟随**：写入在途时到达的整表读取不再覆盖本次收藏，读取落地后
  按曲目最终状态重放。
- **记住上次页面设置失效**：重新打开应用恢复上次停留的一级页恢复正常。
- 发现页歌单标签加载时的高度塌陷与版式跳动。

## 内部

- 组合根改为唯一 `ProviderContainer`，依赖图由 Riverpod provider 显式声明；ADR-0041
  记录迁移口径。
- 新增架构棘轮：`lib/` 内禁止新增 `ChangeNotifier` 状态类，音源管理器完成后收紧白名单。
- 移除 `provider` 直接依赖，加入 `flutter_riverpod` / `riverpod_generator`。

## 注意

- 测试版与稳定版使用同一签名，可直接覆盖安装。
- 测试版走滚动 `beta` 更新清单，会先于稳定版收到后续 0.5.0 的改动。
