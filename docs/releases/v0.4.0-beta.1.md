# Molia 0.4.0-beta.1

0.3.0 之后的第一个测试版：桌面端补上系统媒体集成（输出设备丢失暂停、播放菜单、
桌面入口），移动端重做了平台音频会话的生命周期。

## 新增

### 桌面

- **输出设备丢失自动暂停**：Windows 拔耳机、蓝牙断开、USB DAC 掉电，以及 macOS /
  Linux 默认输出消失时，播放立即暂停，不会继续从内置扬声器满音量外放。新增设备、
  在两个仍然可用的输出之间主动切换都不会误触发；暂停后不自动恢复。
- **Windows 音量合成器显示 Molia**：以前这条音频流显示为 `JustAudioMediaKit`，
  现在与应用同名，能一眼认出。
- **macOS 播放菜单**：菜单栏新增「播放」菜单，含播放 / 暂停、上一首、下一首，与
  托盘菜单是同一批动作，跟随界面语言；键盘、鼠标与 VoiceOver 用户都能用。
- **Linux 桌面入口**：应用菜单可按「音乐 / 播放器」搜到 Molia，系统通知归属应用，
  声明单主窗口并带启动反馈。

## 改进

### 播放与音频

- **打开 Molia 不再打断其他应用**：以前 iOS 冷启动会激活音频会话，覆盖
  「与其他应用同时播放」；现在按设置走，混播设置在冷启动后依然有效。
- **暂停后释放音频会话**：暂停 20 秒、停止或退出后释放会话与焦点，其他播放器可以
  恢复；宽限期内继续播放不需要重新激活。
- **Android 混播真正生效**：「与其他应用同时播放」开启时，导航、语音提示会压低音乐
  并在结束后恢复，而不是抢独占焦点；关闭时保持独占。播放中切换该设置立即生效。
- 通话、Siri 等中断结束后自动续播更可靠；焦点确实拿不回来时给出可重试提示。

## 修复

- 中断导致的暂停不再立即放弃音频焦点——之前放弃后系统不再发恢复事件，通话结束也
  无法自动续播。
- 冷启动只在没有播放时释放会话：恢复上次播放的自动起播不会被释放打断。
- Windows 默认输出按播放后端实际使用的多媒体角色判断，不再只跟随控制台角色而跟丢
  设备。

## 内部

- ADR-0035（平台音频会话生命周期）、ADR-0036（桌面媒体集成）、ADR-0037（gapless
  暂不实现）与平台媒体 checklist；架构测试覆盖各平台媒体声明与桌面入口契约。

## 升级说明

- 测试版与 0.3.0 使用同一签名，可直接覆盖安装；构建号单调递增，应用内更新能正常
  识别。设置 › 更新 › 更新渠道选「测试版」即可收到本版。
- 本项目仍处于快速迭代期，不承诺跨版本数据与协议兼容；需要保留的资料请先备份。
